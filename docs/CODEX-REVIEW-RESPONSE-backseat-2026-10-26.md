# Response to CODEX-REVIEW.md

All findings addressed unless noted. `npm run build`, `npm test` (57 tests), and `npm run e2e` all green.

- **Scheduled unlock/trunk/frunk bypasses PIN** (tools.ts:305 + poller.ts:71) — fixed. `schedule_action` now inherits the wrapped tool's PIN gate (agent.ts's `effectiveGateRequiresPin` holds the schedule request itself for the PIN, same as an immediate call); the stored trigger carries a `pinVerified` bit, and `poller.ts`'s `fireTrigger` re-checks it before dispatching any pin-gated tool, skipping and notifying the owner if it's false.
- **Nine tools report success with zero getState() verification** — fixed for 7 of 9 with a real telemetry field to check: `set_climate_temp` (new `climateTargetF`, driver_temp_setting), `open_charge_port`/`close_charge_port` (new `chargePortOpen`), plus the five already-listed-as-fine wording stays correct. `open_trunk`, `open_frunk`, `vent_windows`, `close_windows`, `nav_send_destination`, `set_scheduled_departure` have **no boolean telemetry field in the real Tesla/Tessie API at all** (trunk/frunk are momentary latches, nav and windows aren't reported back) — re-reading state for them would check nothing meaningful. Instead of inventing a fake field, their wording was softened to "command sent and accepted" rather than "opened"/"done", honest about what the adapter's own `result:true` check (see below) actually confirms. Documented inline in tools.ts.
- **Model text can override a failed verification** (agent.ts:118) — fixed. `Tool.run` now returns `{text, verified}`. `runClaudeLoop` tracks the most recent mutating tool call whose verification failed; if the model's subsequent free-text reply would otherwise be returned, the tool's own (accurate) text is returned instead.
- **Cached/missing telemetry masquerades as verified** (tessieAdapter.ts:63,71,108) — fixed. `locked` is now `boolean | null` (absent telemetry reads as unknown, never a confirmed `false`); `updatedAt` is built from the vehicle's own per-category `timestamp` fields, falling back to wall-clock only when every one is absent; `getState({realtime:true})` passes Tessie's `use_cache=false`, and every tool's post-command verification read uses it.
- **Native scheduled departure advertises a CANCEL that doesn't exist** (tools.ts:285 + agent.ts:154) — fixed by implementing real cancellation instead of removing the (contradictory) promise. Added `cancel_scheduled_departure` tool (calls Tessie's own `schedule_departure` with `enable:false`) and changed `set_scheduled_departure`'s reply to point at it explicitly, instead of saying "Reply CANCEL" (CANCEL only ever touches this app's own SQLite triggers). CANCEL's "nothing pending" reply now also hints at this when a native departure is configured. **Deviation from docs**: SPEC.md/ARCHITECTURE.md still show the old "Reply CANCEL to cancel" wording for scheduled departure — that doc text is now wrong and should be updated to match; left as-is here since the task scope was the code fix, not a doc rewrite.
- **Telegram errors can leak the bot token/PIN to logs** (telegram.ts:25,36) — fixed. The message handler and `bot.start()` are both wrapped so no error object reaches `console.error` directly; only the error's `name` is logged.
- **PIN persisted to memory and resent to Anthropic** (agent.ts:102,170 + memory.ts:32) — fixed. Every `addTurn` call on the PIN-challenge path now writes a redacted placeholder instead of the actual message text (right PIN, wrong PIN, and timeout paths all covered).
- **Adapter calls don't match Tessie's documented contract** (tessieAdapter.ts:126,160,195,201) — fixed: `temperature` param (not driver/passenger split), `activate_rear_trunk`/`activate_front_trunk` (not open_trunk/open_frunk), `command/share?value=` (not `/share?address=`), `schedule_departure` with `enable` + minutes-past-local-midnight (not an ISO string). `fakeTessieServer.ts` updated to the same corrected contract so tests exercise the real shape, not a duplicated bug.
- **HTTP 200 with result:false treated as success** (tessieAdapter.ts:98) — fixed. All command calls go through one `command()` helper that checks the parsed `result` field and throws on `false`.
- **Scheduled dispatches race** (poller.ts:86) — fixed. The poller now awaits each due trigger's `fireTrigger` call in sequence inside one loop (never `Promise.all`/fire-and-forget), and a tick that's still running skips the next interval entirely rather than overlapping.
- **Twilio retries/replays re-execute** (twilio.ts:96) — fixed. `TwilioChannel` tracks processed `MessageSid`s in memory with a 10-minute window and no-ops a repeat.
- **Twilio signature validation breaks behind TLS termination** (twilio.ts:89 + index.ts:153) — fixed. Signature validation now reconstructs the public HTTPS URL from `X-Forwarded-Proto`/`Host` (or an optional configured `PUBLIC_BASE_URL`) instead of the raw local request URL.
- **No authoritative clock/timezone for relative scheduling; past dates accepted** (agent.ts:109 + tools.ts:310) — fixed. The system prompt now states the server's current time and an `OWNER_TIMEZONE` env value on every request; `schedule_action` rejects any `whenISO` more than 5 seconds in the past (small slack for round-trip latency).
- **Invalid scheduled tool names silently discarded** (tools.ts:307 + poller.ts:70) — fixed. `schedule_action` validates the tool name against the registry before ever creating a trigger (returns an error immediately instead); the poller also notifies the owner if a trigger's tool somehow can't be found at fire time (defense in depth).
- **Scheduled dispatch failures invisible to the owner** (poller.ts:89) — fixed. A thrown error from `tool.run()` now sends the owner a failure message via the originating channel before re-throwing for the server log.
- **PIN in plaintext config, non-timing-safe compare, no attempt limit/expiry** (agent.ts:161,163 + index.ts:72) — fixed. `index.ts` hashes `USER_PIN` once at startup (`hashPin`) and never holds the plaintext past that line; `agent.ts` compares with `crypto.timingSafeEqual` against the hash. A PIN challenge now expires after 5 minutes and locks out after 3 wrong attempts.
- **STOP reaches the agent loop and can be model-interpreted** (twilio.ts:94 + agent.ts:186) — fixed. `handleInbound` intercepts `STOP` before any CANCEL/PIN/model handling and returns a silent no-op, so it can never resolve to a tool call.
- **X cancels on Telegram despite being SMS-only** (agent.ts:152) — fixed. The `X` alias now only cancels on `channel === "twilio"`; on Telegram it falls through to the normal agent loop.

No finding was skipped as wrong or out of scope — none of them asked for anything Autopilot/FSD/Summon/speed/drive-adjacent, and nothing here adds such a capability.
